作業フォルダ

ソースコードを編集する場所です。

ステージングエリア

次のコミットに含める変更を選択する場所です。

git add .

ローカルリポジトリ

自分のPC内に保存されるGit履歴です。

git commit -m "ログイン機能を追加"

リモートリポジトリ

GitHub上のリポジトリです。

git push

まず覚えるべきGitコマンド

状態確認

git status

変更されたファイルや現在のブランチを確認できます。

変更をステージング

git add .

変更された全ファイルを追加します。

git add Program.cs

特定ファイルのみ追加します。

コミット

git commit -m "ログイン処理を追加"

Push

git push

Pull

git pull

プロジェクト取得

git clone https://github.com/user/sample-app.git

GitHub上のプロジェクトをローカルへ取得します。

cd sample-app

ブランチ操作

mainを直接編集せず、作業ブランチで開発します。

main
 └─ feature/login

現在のブランチ確認

git branch

ブランチ作成と移動

git switch -c feature/login

ブランチ切り替え

git switch main

初学者向け開発フロー

① mainを最新化

git switch main
git pull

② 作業ブランチ作成

git switch -c feature/login

③ 開発

ソースコードを修正します。

④ 状態確認

git status

⑤ ステージング

git add .

⑥ コミット

git commit -m "ログイン機能を追加"

⑦ GitHubへPush

git push -u origin feature/login
初回のみ -u オプションを付けることで、 以降は git push だけでPushできます。

Pull Request（PR）とは

「この変更を main に取り込んでください」 と依頼するための仕組みです。 

main
 ↓
feature/login
 ↓
開発
 ↓
commit
 ↓
push
 ↓
Pull Request
 ↓
レビュー
 ↓
マージ

PR作成手順

  1. GitHubへPush
  2. Compare & Pull Request をクリック
  3. タイトル入力
  4. 説明入力
  5. Create Pull Request
  6. レビュー依頼

マージ後の作業

mainを最新化

git switch main
git pull

不要ブランチ削除

git branch -d feature/login

最重要フローまとめ

最初はこの流れだけ覚えれば十分です。 
# mainを最新化
git switch main
git pull

# 作業ブランチ作成
git switch -c feature/sample

# 開発後
git add .
git commit -m "機能追加"

# GitHubへ送信
git push -u origin feature/sample

# GitHubでPR作成
# レビュー
# マージ

# 作業終了後
git switch main
git pull
git branch -d feature/sample
